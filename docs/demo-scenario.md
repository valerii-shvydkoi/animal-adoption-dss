# Контрольний сценарій Adoptify

## Підготовка бази

```bash
docker compose exec backend python manage.py seed_demo --reset
```

Локально без Docker:

```bash
cd backend
python manage.py seed_demo --reset
```

Команда очищає дані застосунку та створює один верифікований притулок, чотири ролі, набір котів і собак з різними профілями сумісності, тестові заявки та локальні фото тварин. Зображення зберігаються в репозиторії у вигляді контрольованих демо-ресурсів, тому повторний запуск seed дає однаковий результат.

У базовому стані `user@adoptify.demo` не має пройденої анкети. Це дозволяє перевірити, що персональні рекомендації з'являються тільки після заповнення AHP-форми. Для всіх демо-акаунтів використовується пароль `AdoptifyDemo2026!`.

Якщо потрібно одразу отримати користувача з готовим результатом анкети, можна виконати:

```bash
docker compose exec backend python manage.py seed_demo --reset --with-user-questionnaire
```

## Демо-акаунти

- `user@adoptify.demo` - користувач каталогу без анкети на старті.
- `manager@adoptify.demo` - менеджер притулку "Центр адаптації Adoptify".
- `volunteer@adoptify.demo` - волонтер цього ж притулку.
- `admin@adoptify.demo` - адміністратор платформи.

Окремий акаунт гостя не створюється. Гостьовий стан перевіряється після виходу з системи або в окремому приватному вікні.

## Послідовність перевірки

1. Відкрити каталог як гість, переглянути фільтри, деталі тварини та обране.
2. Додати кілька тварин в обране без авторизації.
3. Увійти як користувач і перевірити перенесення обраного після входу.
4. Відкрити профіль користувача та переконатися, що рекомендацій без анкети немає.
5. Пройти AHP-анкету, зберегти контактні дані та переглянути топ рекомендацій.
6. Подати заявку на адаптацію та перевірити її в розділі "Мої заявки".
7. Увійти як волонтер, переглянути заявки притулку та змінити статус заявки.
8. Увійти як менеджер притулку, перевірити тварин притулку, команду, заявки волонтерів і аналітику.
9. Увійти як адміністратор, переглянути глобальні метрики, аналітику окремого притулку, користувачів і реєстр притулків.

## Що перевіряється

- Каталог не показує персональні рекомендації без результату анкети.
- AHP-форма використовує спрощені порівняння та формує узгоджені ваги.
- Топ рекомендацій сортується за відсотком сумісності, терміновістю та датою створення картки.
- Гостьові фільтри не переходять у профіль авторизованого користувача.
- Після повернення з деталей тварини каталог зберігає сторінку та фільтри, а після F5 повертається до стартового стану.
- Волонтер бачить власних підопічних, а менеджер - усіх тварин свого притулку.
- Менеджер бачить тільки заявки волонтерів свого притулку.
- Адміністратор має доступ до загальної аналітики платформи та окремої аналітики притулку.
- PWA кешує статичні ресурси застосунку; персональні API-дані не кешуються service worker.
