# Демо-сценарій Adoptify

## Підготовка бази

```bash
docker compose exec backend python manage.py seed_demo --reset
```

Локально без Docker:

```bash
cd backend
python manage.py seed_demo --reset
```

Команда очищає дані застосунку, створює один демонстраційний притулок, чотири основні ролі, котів і собак з різними профілями сумісності та локальні фото. Для демо-тварин сидинг завантажує реалістичні фото за видом і породним запитом; якщо мережа недоступна, автоматично створює локальне зображення-заглушку. У стартовому демо-стані `user@adoptify.demo` ще не має пройденої анкети, щоб можна було показати появу рекомендацій після заповнення AHP-форми. Пароль для всіх демо-акаунтів: `AdoptifyDemo2026!`.

Якщо потрібно швидко підготувати стан уже з готовими рекомендаціями, можна додати прапорець `--with-user-questionnaire`. Для основного показу краще використовувати базовий варіант без цього прапорця.

## Акаунти

- `user@adoptify.demo` — користувач без пройденої анкети на старті, з обраними тваринами для демонстрації каталогу.
- `manager@adoptify.demo` — менеджер єдиного демо-притулку, керування тваринами, командою і заявками.
- `volunteer@adoptify.demo` — волонтер того самого притулку, перегляд підопічних і всіх заявок на адаптацію тварин цього притулку.
- `admin@adoptify.demo` — адміністратор платформи, перегляд глобальної аналітики, користувачів і стану системи.

Гість не має окремого акаунта. Для демонстрації незареєстрованого стану потрібно просто вийти з системи або відкрити застосунок у приватному вікні.

## Послідовність показу на одному ноутбуці

1. Відкрити каталог як гість: показати фільтри, картки та обране без переходу на сторінку входу.
2. Додати кілька тварин в обране як гість.
3. Увійти як `user@adoptify.demo`: показати, що гостьове обране переноситься в акаунт, а гостьове сховище очищується.
4. Відкрити профіль і анкету: спочатку показати відсутність персональних рекомендацій, потім пройти AHP-анкету.
5. Перейти до каталогу або результатів: показати топ-3 рекомендації, пагінацію результатів і пояснення сумісності.
6. Подати заявку на тварину, перейти в "Мої заявки" та показати статус.
7. Вийти й увійти як `manager@adoptify.demo`: додати тварину з фото з комп'ютера або URL, переглянути заявки волонтерів.
8. Увійти як `volunteer@adoptify.demo`: переглянути заявку на адаптацію по тварині притулку, побачити відсоток сумісності після анкети або ручну підказку без анкети та змінити статус.
9. Увійти як `admin@adoptify.demo`: показати глобальну аналітику та заявку на верифікацію нового притулку.

## Ключові акценти

- AHP не змушує користувача заповнювати складні матриці вручну: інтерфейс збирає пріоритети через прості порівняння і формує узгоджені ваги.
- Каталог не показує персональні рекомендації без результату анкети, тому не створює хибної впевненості в підборі.
- Гостьове обране ізольоване від акаунтів і переноситься тільки після успішного входу.
- Ролі розділені: адміністратор верифікує платформу, менеджер керує притулком, волонтер обробляє заявки на адаптацію.
- PWA кешує статичні ресурси застосунку або штатно показує стан недоступності мережі; персональні API-дані не кешуються service worker.
