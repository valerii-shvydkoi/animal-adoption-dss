# Технічний аудит Adoptify

Цей документ описує поточний стан проєкту після звірки з дипломом і правила подальшої підтримки.

## Структура

- `backend/` — Django/DRF API, бізнес-логіка, моделі, сервіси, тести.
- `frontend/` — React/Vite PWA, сторінки за ролями, API-клієнт, UI-компоненти.
- `docs/` — дипломна відповідність, wireframes, аудит.
- `docker-compose.yml` — повний локальний запуск PostgreSQL, backend і frontend.

## Backend

- API версійований через `/api/v1/`.
- Основна бізнес-логіка винесена в `core/services`.
- Підбір тварин розраховується через AHP і DSS matching.
- Для заявок на адаптацію використані атомарні транзакції та блокування тварини через `select_for_update`.
- Soft delete тварин не ламає історію заявок.
- Помилки проходять через `core.exceptions.custom_exception_handler`.

## Frontend

- API-запити йдуть через єдиний `frontend/src/services/api.js`.
- Default API path — `/api/v1/`, щоб dev, Docker і production nginx працювали однаково.
- Маршрути відповідають реальним сценаріям диплома; старі backup-сторінки прибрані.
- Рольові кабінети відокремлені через `PrivateRoute`, `VolunteerRoute`, `ShelterRoute`, `AdminRoute`.
- PWA service worker кешує лише статичні ресурси та не кешує конфіденційні API-відповіді.

## Виправлені прогалини

- Додано статус заявки `REVIEWED`.
- Скасування заявки користувачем обмежене статусом `PENDING`.
- Схвалення заявки відхиляє інші активні заявки на ту саму тварину.
- Фронтенд більше не використовує прямі hardcoded backend URL у сторінках.
- Додано маршрут `/catalog`, який уже використовувався в інтерфейсі.
- Прибрано застарілий `old-questionnaire-backup` і невикористаний `AHPForm`.
- Docker frontend тепер реально збирає Vite і віддає SPA через nginx.
- `.env.example` очищено від реальних секретів.
- README переписано під дипломний проєкт.
- Обране розділено на гостьове й користувацьке: після входу гостьові тварини переносяться в акаунт, а гостьова пам'ять очищується.
- Рекомендації СППР показуються лише після проходження анкети; профіль отримав явні поля `has_questionnaire_result` і `latest_questionnaire_result_id`.
- Результати анкети, каталог і деталі тварини використовують один backend-розрахунок AHP/DSS.
- Адміністративна аналітика доповнена метриками СППР, активних заявок, заявок волонтерів і притулків.
- Додано `docs/git-workflow.md` для відновлення Git-репозиторію в дипломній структурі.

## Контроль якості

Перед здачею або демонстрацією виконувати:

```bash
cd backend
.venv\Scripts\python.exe -m pytest
```

```bash
cd frontend
npm run lint
npm run build
```

## Ризики, які варто тримати під контролем

- У production потрібно вимкнути `DEBUG`, задати сильний `SECRET_KEY` і закрити Swagger.
- Реальний `.env` не можна комітити або показувати на демонстрації.
- Для публічного deployment потрібно додати HTTPS на reverse proxy.
- Якщо змінюється AHP-ієрархія, треба одночасно оновлювати анкету, backend validation, тести й опис у `docs/requirements-matrix.md`.
- Якщо змінюється remote GitHub, треба перевірити `git remote -v`, щоб код не пішов у старий навчальний або тимчасовий репозиторій.
